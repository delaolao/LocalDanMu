# 真机演练（Field Trial）

> 目的：用**真实数据**决定这件东西往哪走，而不是靠印象。
> 一次演练只回答三个问题：局域网够不够用？远程模式是不是刚需？卡点在哪？

## 为什么现在做

最近 7 个版本里 6 个是隧道和端口，弹幕本体一个没动。
这些改动全部源自**推测的风险**，没有一条来自真实课堂。

演练就是拿一次课的代价，换掉这个盲区。

## 三阶段

| 阶段 | 做什么 | 成本 | 产出 |
| --- | --- | --- | --- |
| ① 桌面演练 | 3–5 人、20 分钟，手动制造三种网络状态 | 1 小时 | 局域网基线成功率 |
| ② 真课演练 | 一次真实课（哪怕半场） | 一场课 | 真实场景数据 |
| ③ 判定 | 对照下面判据，选 A / B / C | 半小时 | 结论 |

**先做 ①，别跳。** 桌面演练能筛掉大部分"局域网本身就有问题"的假象——
如果正常 WiFi 下首次进入率都不到 90%，那问题根本不在远程模式。

## 判据（先定死，不许事后改）

| 指标 | 怎么算 | 阈值 | 结论 |
| --- | --- | --- | --- |
| **局域网首次进入率** | 30 秒内成功打开页面的学员 / 总学员 | < 90% | 问题在局域网与引导，**不是远程模式**。先改引导和排查页，远程模式维持现状 |
| **远程模式启用率** | 用了远程模式的场次 / 总场次 | < 20% | 远程是**应急** → 走 B（BYO，砍多租户） |
| | | 20%–40% | 灰度区 → 再测一场 |
| | | ≥ 40% | 远程是**常态** → 走 A（产品化，补运营件） |
| **讲师被网络问题阻塞时长** | 单场累计 | > 5 分钟 | 无论 A/B，先修阻塞点 |
| **学员自助率** | 没问人自己进来的 / 总数 | < 80% | 引导页/话术要改 |

> 判据写在演练**之前**。事后调阈值等于没测。

## 怎么用这套文件

```
docs/field-trial/
├─ README.md         ← 本文件：方法、判据
├─ checklist.md      ← 课前 30 分钟照着走，打印出来
└─ _template.md      ← 每场复制一份，起名 2026-11-xx-session1.md
```

填完的场次文件**提交进仓库**，作为决策依据留痕。

## 演练纪律

1. **当天不改代码**。改了就无法归因，数据作废。
2. **只记录，不现场修**。卡住就绕过，把现象记下来。
3. **记事件，不记秒表**。现场没空掐表，只写"发生了什么、怎么处理的、大概多久"。
4. **同一场不混用两种模式**。要么全局域网，要么全程远程，否则无法比较。

## 演练后

把结论写进对应场次文件的最后一节，并在 `docs/topic-tenant.md` 顶部补一行：
"20xx-xx-xx 演练结论：走 X"。这样下次拿起这个项目，不用重新纠结。
