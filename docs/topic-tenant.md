# 议题 TENANT：多用户、域名与授权（暂缓）

> 代号 **TENANT**（租户方案）。讨论于 v0.4.1 之后，结论：**先搁置**，先把技术侧收尾。
> 恢复方式：跟助手说「继续 TENANT」。

## 要解决的问题

固定隧道需要「Cloudflare 隧道令牌 + 一个域名」。现在令牌是作者个人账号的凭证，
如果随安装包分发，会出现：

| 风险 | 后果 |
| --- | --- |
| 令牌共享 | 任何人可在任意机器起连接器，接入作者的隧道 |
| 流量落错机器 | 同一隧道多个连接器时 Cloudflare 轮询分发，学员可能被路由到别人的电脑 |
| 撤销困难 | 令牌外流只能轮换并通知所有人换新 |

另外绝大多数讲师不会自建域名（¥60/年 + Cloudflare 账号 + 约 10 分钟配置）。

## 讨论过的三种架构

### A. 自带（BYO）——现状

每人自己注册 Cloudflare、买域名、建隧道、粘令牌。
作者零成本零责任，但门槛高，普通用户走不通。

### B. 作者账号托管 + 每用户一条隧道（推荐）

```
作者的 Cloudflare 账号
├─ 隧道 t-0001 → u0001.dm.<作者域名> → 用户 A 的电脑
├─ 隧道 t-0002 → u0002.dm.<作者域名> → 用户 B 的电脑
```

用户申请「启用码」→ 作者用脚本建隧道 + DNS + Public Hostname → 下发**该用户专属令牌**。

- 成本：隧道与 DNS 都免费（单 zone 1000 条记录）
- 撤销：删隧道 + 删 DNS，只影响一个人
- 不需要自建服务器
- 代价：令牌仍是作者账号的凭证，但每人一把、可单独吊销

### C. 自建中继

用户只连作者的中继，中继按启用码路由到对应用户（frp / Workers + Durable Objects）。
体验最好，但有服务器成本与运维负担，适合用户量上来之后再考虑。

## 倾向的分档

| 档位 | 能力 | 价格 |
| --- | --- | --- |
| 免费 | 局域网 + 自带 Cloudflare 令牌 | 0 |
| 托管 | 作者域名下的专属子域 + 专属令牌 | 几十元/年 |
| 定制 | 学校自己的域名 + 代配置 | 一次性服务费 |

定位：**不按"域名"收费，按"服务与责任"收费**。
点赞/推荐换授权可以做促销，但难以自动核实，别做成自动门槛。
