# 远程模式：Cloudflare Tunnel

> 状态：**正式功能（v0.3.0 起）**，默认关闭，讲师按需开启。
> 解决的问题：场地 WiFi 不可用（挤爆 / 隔离 / 没有）时，学员用手机流量也能进入。
> 一句话结论：能用，代价是首屏 1～3 秒、单程约 250ms；内容端到端加密，中继看不到正文。

## 它做什么

控制面板的二维码下面多了一张卡：

```
远程模式                            [开启]
场地 WiFi 不稳定时，让学员用手机流量扫码进入。
内容端到端加密，中继看不到消息正文。

        ┌─────────────┐
        │   二维码     │
        └─────────────┘
https://xxx.trycloudflare.com/j/<房间号>
```

点「开启」后：

1. 检查 `%LOCALAPPDATA%\localdanmu\cloudflared.exe`，没有就用 `curl.exe` 从 GitHub 下载一次（约 53MB，之后缓存）
2. 起子进程：`cloudflared tunnel --url http://127.0.0.1:<本地端口> --no-autoupdate`
3. 从它的 stderr 里抓 `https://*.trycloudflare.com`
4. 拼成 `https://<隧道>/j/<房间号>`，生成二维码推到面板

关闭或退出程序时，子进程会被显式 kill。

**更强的保证**：子进程被放进一个 Windows **Job Object**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）。
这样即使应用被任务管理器强杀、或者崩溃，系统也会在进程句柄关闭时连带杀掉 cloudflared——
不会出现"后台还挂着一个隧道"的情况。实测：

| 操作 | cloudflared 进程数 |
| --- | --- |
| 开启隧道 | 1 |
| 点「关闭」 | 0 |
| **任务管理器强杀应用** | **0** |

## 实测数据（本机 → Cloudflare 边缘）

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| 首次打开页面 | 3.15 s | 冷连接，包含 TLS + WS 升级 |
| 再次打开页面 | 1.04 s | 连接复用之后 |
| WebSocket 建立 | 1.35 s | 手机扫码后等的就是这一段 |
| 发一条消息 → 收到 ack | ~0.47 s | 单程约 233 ms |

对比局域网：同一台机器上 WS 建立 + ack 是 **个位数毫秒**。

**怎么读这组数**：

- 发弹幕本身是"发完就不管"，200ms 单程观众几乎无感
- 点赞是"点了要看到变化"，来回 ~0.5s，会有明显延迟但可接受
- 图片上传（300KB）在这种链路下要 3～5 秒，弱网会更久
- 真正难受的是**首次进入**：1～3 秒才看到页面，需要页面上给个"正在连接"的过渡

## 端到端加密（E2E）

目标：Cloudflare 只做转发，看不到消息内容。

**密钥怎么传**

```
https://xxx.trycloudflare.com/j/<房间号>#k=<32 字节 base64url>
                                    └── fragment，浏览器不会发给服务器 ──┘
```

`#` 之后的内容按 HTTP 规范不会出现在请求里，所以 Cloudflare 拿不到密钥；密钥由讲师机在开启隧道时生成。

**哪些连接加密**

只有**同时满足**两个条件的连接才加密：

1. 对端地址是回环（`127.0.0.1` / `::1`）——即 cloudflared 转发进来的
2. 客户端在 WS 握手里带 `&enc=1`——即它确实拿到了 `#k`

局域网连接完全不受影响：明文、零开销、协议不变。

**fail-closed**：远程模式开启期间（密钥存在），凡是从回环地址进来的连接都必须带 `enc=1`，
否则服务端直接回一条 `enc_required` 并断开——不会降级成明文。同理，加密失败时也只会断开，
不会退化成明文发送。观众端在 https 下发现 `#k=` 缺失时会直接提示「链接不完整（缺少加密密钥），请重新扫码」，
连都不会去连。

这意味着**丢掉了 fragment 的二维码链接（转发、手输、截图后重扫）在远程模式下不可用**，
这是有意的：宁可让学员重新扫码，也不让内容以明文经过中继。

**信封格式**

```json
{ "type": "enc", "iv": "<12 字节 base64>", "data": "<AES-256-GCM 密文 base64>" }
```

- 手机端：`WebCrypto` 加密整条消息 JSON
- 讲师端：`aes-gcm` 解密后再校验、限流、过滤
- 广播方向（hello / 新消息 / 点赞 / 配置）由服务端逐连接加密，同一个广播对局域网仍是明文

**验证结果**

| 检查 | 结果 |
| --- | --- |
| 远程连接的 hello 是密文，解开后 `type=hello` | ✅ |
| 信封里搜不到明文 | ✅ |
| 明文消息发给加密连接 → 被拒（`bad_enc`） | ✅ |
| 加密消息 → 正常 ack | ✅ |
| 真实浏览器（Edge headless）打开远程页 → 状态显示「远程模式」 | ✅ 说明密文被浏览器正确解开 |
| 局域网明文链路 | ✅ 不受影响 |

**仍然可见的**：连接时间、消息条数与长度、seq、点赞数。这些是转发必需的元数据，无法隐藏。

**ack 仍是明文**：它只包含 `msgId/status/seq/retryAfter`，没有消息内容。

## 固定域名（Named Tunnel，推荐）

Quick Tunnel 的地址每次都会变。给培训材料印二维码、或者希望"断线重连后学员不用重新扫码"，
就需要一条**固定隧道**——用你自己的 Cloudflare 域名。

### 控制台配置（一次性）

1. 打开 https://one.dash.cloudflare.com → **Networks → Tunnels → Create a tunnel**
2. 连接器选 **Cloudflared**，名字随意（如 `localdanmu`），保存
3. **Public Hostname → Add a public hostname**：

   | 字段 | 值 |
   | --- | --- |
   | Subdomain | `dm` |
   | Domain | 你的域名（例：`teachergeng.space`） |
   | Type | `HTTP` |
   | URL | `localhost:8080` |

4. 回到隧道详情页，复制**令牌**（点命令框右侧的复制按钮——屏幕上显示的是打码的 `***`，手抄无效）

> ⚠️ 不要执行页面提示的 `cloudflared.exe service install <令牌>`。那是把 cloudflared 装成
> Windows 服务（开机自启、脱离程序管理）。本项目自己会拉起 cloudflared，不需要装服务。

### 程序里怎么用

控制面板 → **设置与网络 → 固定隧道**：

- **公开域名**：填 `dm.teachergeng.space`
- **隧道令牌**：粘贴上面复制的令牌

填好后点「远程模式 → 开启」，地址就固定成 `https://dm.teachergeng.space/j/<房间号>`。
令牌只存在本机 `settings.json` 里，不上传任何地方。

### 固定域名带来的好处

| | 临时隧道 | 固定隧道 |
| --- | --- | --- |
| 地址 | 每次随机 | 永远不变 |
| 自动续连后 | 地址变，学员要重新扫码 | 地址不变，学员刷新即可 |
| 能印在培训材料上 | 不能 | 可以 |
| 令牌 | 不需要 | 需要（本机保存） |

### 常见错误

| 提示 | 原因 |
| --- | --- |
| `Provided Tunnel token is not valid.` | 令牌不对/被截断/已删除 |
| 页面 1033 | 隧道连上了，但没配 Public Hostname |
| 页面 502 | Public Hostname 指的端口和程序实际端口不一致 |

## 自动续连

隧道进程崩溃、或者 Cloudflare 侧把连接掐了，默认行为是显示错误、等讲师手动点「重试」。
勾上「自动续连」后，程序会在 3 秒后自动重开隧道，无需人工干预。

**注意**：Quick Tunnel 每次重开都会分配新的随机域名，所以

- 二维码 / 投屏引导页会自动更新成新地址
- **已经在页面上的人会掉线，需要重新扫码**

要避免这一点，只能改用 Named Tunnel + 固定域名（见"后续还可以做"）。

讲师主动点「关闭」时不会触发续连——程序会记住"这是主动关闭"。

## 微信里的「未备案」提示

用固定域名后，学员在微信里第一次打开会看到：

```
将要访问  https://dm.你的域名/...
该网站未完成ICP备案，无法确认其安全性...
[继续访问]
```

这不是程序的问题，是微信对**所有中国大陆境外服务器**的统一提示。应对方式：

| 方式 | 说明 |
| --- | --- |
| 点「继续访问」 | 一次性，最省事；本程序已经在页面顶部加了提示条 |
| 右上角 ··· → 在浏览器打开 | 走系统浏览器，不会有这个拦截，体验更好 |
| 局域网地址 | `http://192.168.x.x:8080/j/...` 是 IP，不触发备案拦截 |

观众页顶部会自动出现一条提示（仅在「微信 + 远程模式」时显示）：
「微信若提示『未备案』，点继续访问即可；也可用右上角 ··· → 在浏览器打开」。

> 想彻底去掉这个提示，只能做 ICP 备案 + 国内服务器，那和"数据不出讲师电脑"的定位冲突，不建议。

## 已知限制

| 项 | 说明 |
| --- | --- |
| ~~未加密~~ | **已做端到端加密**，见下一节。仍可见的只有元数据（谁、什么时候、发了多长的消息） |
| 随机域名 | 每次开启都变，房间结束即失效；对"每场一个二维码"的用法没问题 |
| 依赖 Cloudflare | 官方把 Quick Tunnel 定位为测试用途，无 SLA、有限速 |
| 需要公网 | 讲师机自己也得能上网；如果场地出口也烂，隧道救不了 |
| 体积 | cloudflared 53MB 是**按需下载**，不打包进安装包（否则 1.8MB 的安装包会变成 50MB+） |
| 防火墙 | 不涉及——隧道是出站连接，不需要开端口 |

## 为什么不做进安装包

整个应用重写成 Tauri 后安装包只有 1.8MB。把 cloudflared 内置进去等于把体积优势还回去。
所以选择"首次使用时下载"，代价是第一次开启要等 10～30 秒（取决于网络）。
