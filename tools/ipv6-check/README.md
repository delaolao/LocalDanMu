# 现场 IPv6 自检工具

一个 0.27MB 的单文件小工具，回答现场最常见的一个问题：

> **学员用手机流量，能不能直接访问到讲师这台电脑？**

如果能，那么场地 WiFi 再烂都不影响——手机走 5G，直接连到讲师机的公网 IPv6，不经过任何中继服务器。

## 为什么需要它

"场地开了 IPv6"和"手机流量能连进来"是两件事：

| 层级 | 常见坑 |
| --- | --- |
| 运营商 | 只给 IPv4，或 IPv6 只有出站 |
| 路由器 | IPv6 功能没开 / 没下发前缀（SLAAC） |
| 路由器防火墙 | **默认拦掉所有 IPv6 入站**（最高频） |
| Windows | 网络配置文件是"公用"，防火墙拦入站 |
| 会场 | 访客 Wi-Fi 本身只有 IPv4，或开了客户端隔离 |

前三层在笔记本上都能看到一点线索，最后一层只有"让手机真的连一次"才能证明。这个工具就是把这一步做成扫码。

## 怎么用

把 `ipv6-check.exe` 拷到讲师机上，在**要用的那个 Wi-Fi 下**双击运行（或在 cmd 里跑）：

```
ipv6-check.exe
```

它会：

1. 列出本机所有地址，标出公网 IPv6（`2408:` / `240e:` 这种）
2. 探测出站 IPv6 通不通
3. 起一个临时 HTTP 服务（默认 8099，双栈）
4. 自动弹出一个二维码

然后：

- **手机关掉 WiFi、改用移动数据**
- 扫屏幕上的二维码
- 页面显示「✅ 入站可达」= 这条路能用；打不开 = 被上面某一层拦了

命令行参数：

```
--port 8123      换端口
--minutes 3      跑 3 分钟（默认 10）
--no-qr          不生成二维码，只打印链接
--no-open        生成二维码但不自动打开看图程序
```

## 结果怎么读

| 看到的输出 | 含义 | 下一步 |
| --- | --- | --- |
| 公网 IPv6 有值 + 出站 ✅ + 手机打开 ✅ | 全通 | 可以把 IPv6 链接放进二维码，手机流量直接入场 |
| 公网 IPv6 有值 + 出站 ❌ | 有地址但上不了网 | 上游没真正开通，或 IPv6 网关不可达 |
| 公网 IPv6 有值 + 出站 ✅ + 手机打不开 | **入站被拦** | 路由器 IPv6 防火墙关掉，或加一条允许入站规则 |
| 公网 IPv6 无 | 这个 Wi-Fi 没有 IPv6 | 进路由器开 IPv6；或判定场地不支持，改用 Cloudflare Tunnel |

## 验证记录

- 本机（Wi-Fi 只有 IPv4、带 Tailscale）：正确识别出"没有公网 IPv6"，并给出排查清单
- 服务端：`curl http://[::1]:8099/` 返回「入站可达」页面，控制台记到 `[1] IPv6 ::1`
- 二维码：BMP 落盘后能正常识别出编码内容（198→330px，便于远距离扫）

## 边界

- 只做**诊断**，不改动弹幕程序，也不占用它的 8080 端口
- 需要管理员权限才能改防火墙；本工具只检测、不改
- 防火墙弹窗请务必选「允许」并勾选专用网络，否则结果一定是"打不开"
- 二维码走的是系统看图程序（BMP），不需要任何第三方库
